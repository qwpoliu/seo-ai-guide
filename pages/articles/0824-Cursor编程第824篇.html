Cursor编程第824篇

哈喽，各位码农朋友们，我又来啦！今天是《Cursor编程》系列的第824篇——你没看错，824篇，比我写过的代码行数还多（笑）。但说真的，用Cursor编程这么久了，每次打开编辑器还是能发现新惊喜。今天咱们就聊聊我最近玩Cursor的几个心得，全是干货，不打官腔。

为什么我还在用Cursor？

你可能要问：“市面上的AI编程工具那么多，Copilot、Codeium、Tabnine…凭啥Cursor能撑到第824篇？”答案很简单：它懂得上下文，而不是瞎猜。普通工具只会根据你当前光标位置补全下一行，但Cursor能看懂你整个文件、整个项目，甚至你刚关掉的另一个tab。有一次我写一个复杂的React组件，刚写了`const handleSubmit = () => {`，Cursor直接给我补出了表单验证、API调用和错误处理，连loading状态都帮我封装好了。我当时就一个感觉：这货是不是偷看了我的脑子？

第824篇的由来：一个“玄学”发现

别误会，不是什么技术突破。而是我偶然发现，Cursor的提示质量和你的注释详细程度成正比。以前我写注释都是“// 获取用户列表”，结果它给我的建议经常跑偏。后来我改成“// 获取用户列表，包含头像和昵称，按注册时间降序，只返回前20条”，它直接生成了一个带分页和缓存的完整函数。从那以后我养成了写“话痨注释”的习惯——你越啰嗦，它越聪明。所以第824篇，其实就是想告诉你：跟AI交流，千万别客气，把你想要的结果全说出来。

三个让你效率翻倍的Cursor技巧

1. 用`@`符号召唤上下文

在Chat窗口里输入`@file:xxxx.ts`，它就能直接读取那个文件的内容。我经常在写新模块时，先输入`@file:api.ts @file:types.ts`，然后说“帮我写一个类似createUser的updateUser函数”，它自动复用之前的类型定义和API风格，连错误处理逻辑都给你抄过来。这比从头写高效十倍。

2. 别只依赖补全，试试“/fix”魔法

遇到报错？别自己debug了。选中整个报错区域，按Ctrl+K（mac是Cmd+K），输入“/fix”，Cursor会自动分析错误原因并给出修复方案。有一次我死活找不到一个类型错误的源头，结果它直接定位到我一个月前写的一个接口返回格式问题——人家连git历史都帮你看了。

3. 用“Write Code in Lisp”风格？不，用“Plan then Code”

新功能开发时，别急着写代码。先在Chat里说：“帮我规划一个用户权限管理模块，包括角色、权限点、中间件三个部分，给出文件结构和核心逻辑”，它会生成一个markdown大纲。确认没问题后，再说“按照这个规划生成代码”。这样写出来的代码结构清晰，几乎不需要重构。这是我从第500篇开始一直用的方法。

别被“AI会抢饭碗”这种话骗了

最近总有人问我：“Cursor这么厉害，程序员是不是要失业了？”我只能说：工具越强，用工具的人越贵。我身边那些靠堆if-else混日子的同事确实慌了，但真正懂业务、懂架构的人，用Cursor一天能写完过去一周的代码。第824篇我想分享的核心价值观是：学会和AI协作，而不是对抗。你把逻辑想明白，让Cursor帮你写样板代码、优化细节、甚至查漏补缺——它就像你身边一个24小时在线的顶级码农，而且不会跟你抢功劳。
